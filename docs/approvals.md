# Assigned material review

Authors with current generate permission can request review of an unapproved saved SCRIPT, POST, CAROUSEL, generated IMAGE or ready VIDEO version by a verified OWNER/ADMIN/MANAGER/CLIENT_APPROVER in the same organization. Request identities are actor-bound and idempotent. Only one pending request per material is allowed. An old pending request must be cancelled before another is created. The inbox includes requests created by or assigned to the current user; organization managers can inspect all requests. Reviewer choices expose names and roles, not email addresses.

Only the named assignee with current approve permission can approve, reject or request changes. An author or current manager can cancel. Rejection and change requests require a reason. Approval atomically applies the existing material transition and records the decision; it does not generate video or publish anything. A changed or independently approved material cannot be approved through a stale request. Retry of an identical terminal decision returns the stored result; different decisions conflict. Exact reviewed content remains visible, and terminal decisions/request identities cannot be changed or deleted. Audits contain identifiers and version, not comment or material text.

Migration 0066 introduced SCRIPT requests. Additive migration 0067 adds explicit POST/CAROUSEL targets and a captured carousel lifecycle revision. Exactly one target is allowed. Tenant/entity/version foreign keys and the identity trigger prevent cross-tenant or cross-brand references. Existing script request input/hash normalization is unchanged. Archiving and restoring a carousel invalidates the old request even if content version is unchanged. Authors cancel and submit the current lifecycle explicitly; archived carousels cannot be submitted or approved.

HTTP mutations use existing authentication, Origin validation and shared rate limiting. The form appears only for saved unchanged content. The inbox uses bounded cursor pagination and rechecks current membership. One in-app notification is inserted atomically with the request and links to the inbox. Posts display the requested body and hashtags. Carousels use the existing canvas renderer for requested slide artwork and show every slide's text, caption and hashtags. Rendering errors are visible.

Additive migration 0068 adds IMAGE requests with version 1 and a server-captured SHA-256 checksum. Generated image output is already immutable; each regeneration creates a different image. Exactly-one-target constraints and the evidence trigger now include the image and checksum. The studio loads reviewers on demand. Preview access is scoped to the requester, assignee or current organization manager, uses private storage URLs valid for 60 seconds, and rechecks membership, image readiness and checksum after signing. Responses expose no raw storage key or checksum. Deleted images remain identifiable only by scrubbed metadata; prompts and files are not copied into approval requests. An already issued URL can remain usable until its short expiry or object removal.

Additive migration 0069 adds VIDEO requests bound to the ready stage revision and the current cover revision. Switching to another cover and back still invalidates the previous request. The existing video authorization helper is reused inside the request/decision transaction, including active avatar, current approved script and current subject-scoped consent checks. The preview signs both the final video and its selected cover, then checks authorization, consent and both revisions again. Only metadata remains visible when consent is revoked; review cannot grant access to unavailable media. Request cancellation remains possible. Preview URLs expire after 60 seconds; revocation blocks new URLs and decisions but cannot retract an already issued storage URL immediately.

Validation: workspace/test-source TypeScript, ESLint, production build, 589 tests across 85 files, and five Chrome scenarios including full MVP video playback/approval and images, scripts and post/carousel request → exact-version review → actual database approval. Tests cover duplicate/concurrent decisions, stale edits, carousel archive/restore, foreign tenant/brand and unassigned actor denial, immutable receipts, request notifications, no-store and internal-field exclusion. Image tests also cover checksum immutability, private preview access, deletion and membership revocation during signing, and scrubbed history after cleanup. Mobile layout was checked at 390px and image review screenshots inspected. Video tests verify cover-change races during URL signing, change-back revision fencing, immutable decision identity, concurrent approval and consent revocation. The video full-page screenshot has capture artifacts and is not treated as full visual acceptance. Disposable verification cleaned its resources.

Remaining: email delivery, broader client portal and approval policy. Existing direct role-based approval remains available; assigning a request does not silently introduce an exclusive approval policy. No external provider or SMTP is required for these workflows. Production infrastructure and full-platform readiness remain separate acceptance work.
