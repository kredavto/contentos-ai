# Image generation integration

Image Studio now connects a validated API request to a durable database task, a separate BullMQ worker, a reserved credit balance, private JPEG storage, review/approval and deletion. The provider remains replaceable. Existing photo uploads and video covers retain their behavior and limits. Real generation requires configured OpenAI credentials/model and S3; fixture output is visibly identified as demo.

The adapter uses the official [Images generation endpoint](https://developers.openai.com/api/reference/resources/images/methods/generate), checked on 2026-10-12. One request asks for one opaque PNG at medium quality, with one of three product dimensions: 1024×1024, 1024×1536 or 1536×1024. Prompt length is at most 4,000 characters. The operator explicitly selects an allowlisted GPT Image model; no fallback silently changes the model or price. Documented GPT Image outputs are base64, so response URLs are never fetched. A diagnostic `x-request-id`, when present and valid, is recorded as a request reference; it is not a retrievable image id. Missing token usage and monetary cost remain null.

Transport is fixed to the official HTTPS origin, rejects redirects, has a 210-second timeout and performs no automatic retries. The HTTP JSON body and decoded image both have limits (24 MiB decoded image). Responses require exactly one canonical-base64 PNG with the requested dimensions. Correlation ids are validated before becoming headers. Raw provider errors, prompts, bodies and credentials are not returned in domain errors.

Known 4xx rejection (excluding ambiguous 408/409) is marked definitive; 401/403 report configuration required and 429 reports rate limiting. Network failure, cancellation after dispatch, 5xx, redirects, malformed output and unexpected media are **RECONCILIATION_REQUIRED**. A pre-aborted operation never sends a request. The remote endpoint is not assumed idempotent. An idempotency key in OperationContext does not make it safe to replay a request.

Before any private storage write, `normalizeGeneratedImage` must fully decode the raster, validate exact dimensions, reject animation/corruption/excessive pixels, strip source metadata and re-encode JPEG within the existing 3 MiB storage bound. Header validation in the adapter alone is insufficient. Uploads still reject inputs over 3 MiB; generated inputs have a separate 24 MiB bound.

The `generated_images` table stores immutable actor-bound intent, provider/model, reservation and deterministic tenant-scoped object key. Migrations 0046–0048 add the table, state/identity guards, approval/output constraints and a GENERATE_IMAGE usage policy (initially 8 credits, read from the database by the UI). A tenant may have at most four active tasks and 200 non-deleted records; this reserves space for up to 600 MiB of normalized image output, separately from the existing photo quota.

`contentos-images` dispatches persisted tasks with stable queue ids and concurrency one. A 300-second fenced lease covers the 240-second processor budget. Only abandoned pre-submission work may be reclaimed, with at most three claims. SUBMITTING is committed before calling the provider. An expired SUBMITTING lease becomes RECONCILIATION and is never resubmitted. Changed provider/model configuration fails an old queued task rather than silently rerouting it.

Successful metering is persisted before normalization/storage; absent metering stays unknown. Billing currency is captured with the provider/model before submission, so even a lost response retains the correct currency. Capture happens once in the same tenant-locked transaction that marks the stored result READY, after another actor/lease check. Definitive failure releases the reservation. Uncertain remote results and lost storage acknowledgements also release the customer reserve, retain the RECONCILIATION record and possible external expense, and schedule cleanup; the platform absorbs a possible vendor charge for an unavailable result. A new generation requires a new explicit user intent. Financial reports include image submissions (including deleted/uncertain ones) and count unknown cost without inventing zero or margin.

Durable notifications announce ready images to approvers and failed/uncertain jobs to editors. Receipt deduplication prevents repeated alerts; deleted images and already-approved ready results are skipped. Notification links open Image Studio without exposing prompts or media URLs.

Writers request/delete; approvers approve immutable results. Ordinary brand members may preview. The download endpoint requires approval. A preview necessarily exposes image bytes to the reviewer; approval is a publishing workflow gate, not DRM. Signed URLs last 60 seconds. Images are standalone outputs: automatic calendar attachment, social image publishing, use as avatar source/cover background and image editing are not yet connected.

Deletion immediately blocks new preview/download requests and fences completion. Held reservations are released, captured ones are not refunded. Cleanup waits through an active lease plus 60 seconds, retries failed deletes with backoff, scrubs the prompt/name/reference/checksum after success and sweeps the same key for 24 hours to remove late writes. Usage/reservation/audit evidence remains. Failed and uncertain jobs also clean orphan objects. This deletes application-held files; no unsupported provider-side image deletion API or external retention guarantee is implied.

Configure both web and worker with IMAGE_PROVIDER, IMAGE_GENERATION_ENABLED, OPENAI_API_KEY, OPENAI_IMAGE_MODEL and private storage settings. Local/CI fixtures require MOCK_IMAGE_FILE, which may contain `{size}` (for example `/tmp/image-{size}.png`) to choose the matching preset raster. Production refuses fixture providers. The feature defaults to disabled; missing configuration is shown honestly.

Tests use injected HTTP transports and local raster fixtures only. No live OpenAI request or charge has been made. Current verification and remaining production dependencies are recorded in [implementation status](IMPLEMENTATION_STATUS.md).
