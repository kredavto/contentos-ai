# Financial evidence in the operator console

`GET /api/admin/finance` is a guarded, audited operator report, available to SUPPORT and ADMIN behind `PLATFORM_ADMIN_ENABLED`. Tenant roles grant no access. The browser requests it explicitly; opening the console does not automatically run aggregates. The route has a shared per-user limit of 15 requests per 15 minutes. Migration 0037 adds period/tenant indexes to calls, jobs, ledger and settlement tables. Each database statement has a five-second timeout; timeouts return an error, never a partial successful report. A repeatable-read transaction provides one snapshot for the report and its audit event.

Input: required `from` and `to` ISO instants, optional tenant UUID, `paymentMode=LIVE|TEST` (default LIVE), `groupBy=USER|BRAND|PROVIDER` (default BRAND). The interval must be positive and at most 93 days. It is half-open: from included, to excluded. The browser uses UTC date boundaries. Money sums and counts are decimal strings, preserving SQL bigint/numeric precision beyond JavaScript's safe integer range. The UI formats money without converting it to Number.

## Sources and definitions

- **Confirmed receipts**: immutable `payment_settlements` joined one-to-one to their `billing_orders`. The period is settlement recording time, not a guessed provider transaction date or recognized-revenue schedule. LIVE excludes test orders; TEST includes only test orders. Pending orders and duplicate settlement delivery do not add receipts. Amounts are gross collected amounts before refunds, taxes and payment fees, in minor units. No receipt/customer/payment-method payload is returned.
- **Known AI costs**: all recorded `ai_calls` starting in the period, including retries and failed/unknown calls. Nonnegative known costs are summed separately per stored currency in millionths. Missing or invalid negative costs are counted as unknown, not treated as free usage. A known zero remains distinguishable from missing data. This is not the complete provider bill: adapters do not yet capture all provider/video/storage/caption expenses. Payment mode does not filter AI calls; the provider grouping exposes the recorded sources, including development fixtures when run in a development database.
- **Cost/user and cost/brand**: calls attributed through the original job's requesting user and brand. No allocation of an organization's subscription receipts to individual brands/users is invented. Provider grouping is also available. At most 50 currency/entity groups are returned, ordered by call count with deterministic ties; `groupsTruncated` explicitly flags more groups. Currency totals always cover all matching calls.
- **Internal resource cost**: immutable usage-ledger CAPTURE entries recorded during the interval, summed separately for AI_CREDITS and VIDEO_SECONDS. Grants, purchases, reservations and releases are not charges. Resources are not converted to money.
- **Coverage**: jobs created during the interval with no nonnegative monetary AI-call evidence anywhere in their history, with a separate count for video jobs. Queued/failed/unsubmitted jobs can be included, so this is not a count of billable external operations. It also does not certify complete cost coverage for jobs that have one known call but additional unmetered expenses.

`grossMargin` intentionally remains null. Recognized net revenue, refunds/fees, full provider/video cost capture and explicit FX evidence are not yet available. The UI states this limitation instead of subtracting incomplete USD costs from RUB receipts. Full gross-margin and per-video unit economics remain part of the outstanding specification; this report establishes the source-backed receipts, recorded-call costs, attribution and resource side of that work.

The report selects no job inputs, model outputs, credential envelopes, emails, webhook payloads or API secrets. Audit metadata contains only period, grouping, payment mode and optional tenant ID. Tests cover authorization/revocation, window bounds, tenant filtering, duplicate settlements, test/live separation, partial usage capture, unknown/zero cost distinctions, exclusive end timestamps, multiple currencies, large exact sums and bounded groups with untruncated totals. Provider observations used in tests are fixtures; no real payment or expense is created by these tests.
